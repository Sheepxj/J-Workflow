# 实施进度

本文件记录实际已验证能力；总体方案见 [节点多次执行机制设计与实施计划](节点多次执行机制设计与实施计划.md)。

## 阶段一：V2 协议与编译校验

已实现：

- 与旧 `Node` 分离的不可变节点、连线、循环和工作流定义。
- 可序列化的声明式输入绑定与条件；递归复制 JSON 配置，避免调用方修改嵌套数据。
- 正数预算和重试策略校验，`maxAttempts` 包含首次调用。
- 显式循环区域、回边、端口、出口可达性和去除声明回边后的 DAG 校验。
- 首版明确拒绝嵌套/重叠循环、未知节点类型和未声明的并行出边。
- 固定的编译结果索引及定义内容摘要。

测试基准：原有 Java 测试 25 项通过；增加 9 项契约及编译测试后，34 项测试通过。

旧行为核实：`maxRetries = 2` 表示总共尝试 3 次；旧引擎仍在回调启动前拒绝环。V2 尚未接入旧执行入口。

协议补充：V2 顺序节点只允许一条无条件出边，排他路由要求唯一默认边；多条件命中在运行时报告路由错误。普通节点类型来自注册执行器集合，LOOP/XOR 为内置控制语义。首版 `CURRENT_ITERATION` 指当前轮次，不回退读取上一轮。

环境限制：当前仓库缺少 `scripts/restart-java-workflow.sh`，无法执行仓库说明中的重启脚本。Java 21 与 Maven 可用，已通过实际模块测试验证；尚未进行容器部署或重启验证。

后续工作：运行模型与执行入口、事件调度、结构化循环、真实执行器、嵌套与并行，以及持久化断点和暂停/继续。

## 阶段二：内存调度与结构化循环

已实现独立运行实例、节点逻辑执行、尝试记录和轮次作用域，通过队列推进，不再递归执行前驱。重试使用定时到期状态，超时调用未实际结束前保留物理容量；迟到结果不发布输出。

已验证三轮循环、零轮退出、最后允许一轮达标、轮数耗尽、循环内重试、重复令牌与结果、缺失输入、预算限制、协作取消和 2000 节点长链路。内存暂停与节点前断点已实现：当前调用可以提交，后继令牌保留，继续后推进。

新增 13 项调度测试，与阶段一及旧测试合计 47 项通过。此阶段尚未对接 HTTP 运行入口、持久化存储和服务重启恢复；内存暂停不等于持久化断点。嵌套循环及并行仍未实现。

## 阶段三：V2 API 与业务调用边界

新增独立 V2 运行 API，提供创建、查询、增量事件、暂停、继续和取消；使用受限线程池及共享定时调度推进。旧入口仍保留原执行路径，V2 只接受版本 2，不会自动降级。

新增可配置 MOCK、LLM 和 PLUGIN 的单次调用实现。LLM 使用固定输入且不读取旧全局聊天历史，流式事件关联执行和尝试；插件调用持有私有旧节点视图并恢复线程上下文。二者不经过旧 AbstractNodeExecutor 的重试/共享输出写入。

新增 4 项 HTTP 与调用边界测试，51 项 Java 测试通过；详情和请求示例见 [V2 工作流使用说明](V2工作流使用说明.md)。持久化、嵌套及并行仍在后续阶段。

## 阶段四：持久化断点和租约恢复

新增可选 JDBC 存储，以行锁、revision 和同事务状态快照提交输出、令牌及待派发任务，支持数据库持久化的暂停与继续。增加 30 秒运行租约，保护多调度器接管；旧持有者的迟到结果不能推进运行。

待派发 READY 尝试可以恢复；结果未知的 RUNNING 尝试转为 INTERRUPTED，根据节点配置和尝试预算安全重试或暂停等待人工核实。新增人工结果确认/重试接口，保持原逻辑执行 ID。

新增 6 项 JDBC 故障边界测试，总计 57 项 Java 测试通过。已验证 H2 MySQL 模式、文件数据库关闭重开、调度器更换、提交回滚、待派发恢复与租约过期接管。真实 MySQL 容器与完整服务重启尚未验证：当前 Docker daemon 未启动，仓库原说明引用的重启脚本不存在。

剩余范围包括嵌套循环、配对并行分叉/汇聚、更多旧 DSL 兼容样例、外部幂等集成与完整部署验证。目标尚未全部完成。

## 阶段六之一：失败路由、兼容与工具幂等

新增 SUCCESS/FAILURE 连线结果分类与独立 NODE_ERROR 输入来源，失败节点保留 FAILED 状态。重试耗尽后只激活一次处理路径，已处理的并行分支失败可以正常汇聚，错误数据不混入成功输出。

旧引擎端到端回归验证正常链路引用、错误分支跳过和预设错误输出继续。插件经 Link HTTP 路径传递稳定幂等键，本地 HTTP 故障模拟验证三轮逻辑执行、六次请求、三次副作用；不把该结果外推为所有外部系统都支持恰好一次。

同时修正完整工程存在双 DataSource 时的选择，JDBC 断点显式写入 workflowDataSource。83 项测试和 Maven verify 通过。完整部署与服务进程重启验证仍待完成。
