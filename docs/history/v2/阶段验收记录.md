## 实际进程验证

使用 Java 21、MySQL 8.0.42 和打包后的 workflow-java.jar，通过 `scripts/verify-workflow-v2-restart.ps1` 验证。MySQL 使用本次创建的数据目录、数据库和空闲回环端口，未使用已有业务数据库。

验证包含三个不同的 Java 进程：

1. 运行在生成节点前暂停，确认开始节点已提交后终止进程。
2. 重启后原 runId 保持 PAUSED，继续三轮至 SUCCEEDED；开始节点执行 ID 保留，共 8 条逻辑执行，结果为 draft-3。随后通过 HTTP 验证并行结果，并通过断点探测 LLM 已注册，取消探测以避免调用模型。
3. 另建受控慢节点运行，在 RUNNING 时终止进程。再次重启，等待租约过期，原执行进入 RECOVERY_REQUIRED，原尝试记录 INTERRUPTED。提交核实结果后继续，原 executionId 保留，共 4 条执行，最终 SUCCEEDED。

## 验证边界

- 已完成独立 Java 服务与真实 MySQL 的进程级重启验证；Docker 镜像和原播客平台整套 Compose 未进行部署验证，当前环境的 Docker daemon 未运行。
- 未调用付费模型或使用真实外部工具凭据。模型调用边界使用替身测试，HTTP 工具幂等使用本机故障模拟服务验证；提供幂等键不代表任意外部系统都支持恰好一次副作用。
- 交付结构化循环及明确配对的并行区域，不宣称支持任意交叉控制图、同层嵌套并行、节点内部任意代码行恢复或自动迁移全部旧 DSL。
- 前端编辑器改造不属于本次 Java 引擎实施范围，V2 通过独立 API 接受定义。
